# Renames that CONTRADICT a pre-existing Ghidra/inherited name, with the evidence:
#
# 0x5590a0 biped_update  (was unit_update)
#     The object_type_definition table at 0x0069bfdc has one row per object type; the row's
#     +0x34 column is that type's per-tick update. The biped row (0x0069b4f0, group `bipd`,
#     object_size 0x550) carries 0x5590a0 there and the unit row (0x0069b428, group `unit`,
#     object_size 0x4cc) carries 0x5625b0. So 0x5590a0 is the biped column, and the name
#     unit_update belongs to 0x5625b0. Reading the rows out of .data is the whole proof;
#     see out/phase4/units_types_notes.md.
# 0x5625b0 unit_update  (was FUN_005625b0)
#     Same table, the `unit` row's +0x34 column. It is also the only function in the module
#     that reads the driver at unit 0x324 and folds that occupant's control_flags and aiming
#     vectors into its own, which is what a unit update does and a biped update does not.
# 0x565a70 unit_clear_weapon_switch_state  (was unit_update)
#     50 bytes duplicating the tail of 0x5659c0: it clears the weapon-switch flag bits and the
#     0x348 timer and returns. It has nothing to do with updating a unit, and the real
#     unit_update is 0x5625b0 (above), so the inherited name is doubly wrong here.
# 0x558eb0 unit_recalculate_position  (was unit_refresh_anchor_position, this repo's own
#     earlier phase-4 name)
#     That name asserts a write the function never performs. The cached point at object+0x1c is
#     only read; every value derived from it feeds real_is_valid/__isnan calls whose results are
#     discarded (a compiled-in ASSERT chain). The only effect the function has is calling
#     object_set_position_and_recalculate (0x4f52c0), once unconditionally and once more if that
#     call displaced object.position by more than 2 world units.
# 0x560c70 unit_get_hud_interface_tag_id, 0x560cb0 unit_get_seat_hud_interface_tag_id
#     (both were guessed "permutation" lookups): they resolve UnitUnitHudInterface.hud.tag_id.
# 0x560f20 unit_commit_speech  (was a guessed "set_animation_state"): it block-moves 0xc dwords
#     into unit 0x388 or 0x3b8, i.e. it commits the speech/dialogue queue.
# 0x561990 unit_choose_dialogue_variant, 0x561a00 unit_pick_random_dialogue_variant
#     (both were guessed "permutation" selection): they pick a UnitDialogueVariant.
